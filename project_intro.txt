# RD2017004-MESClient

凌聚農業 MES（製造執行系統）Client 端，前後端同在一個 Web 專案中。
業務資料（製令、製程、庫存、人員、下拉選項）幾乎都來自 ERP（RD2017004-ERP-Web）的 api/Version1/*，本專案自有資料表很少。

## 開發重點注意

    - 要確認 ERP 端的行為時，回 ERP 專案讀原始碼，不要只憑本專案的 LCERP_* 欄位名推測
    - DI 自動註冊：類別與介面名稱都以 "Logic" / "Service" 結尾即自動掃描注入 (AddAutoDi)，
        預設 Scoped，可用 [AutoInject] 改生命週期
    - 前端 JS 改動後，發佈時需跑 `npx gulp release` 加版本戳（gulpfile.js
        （WebSite.csproj 已於 BeforePublish 自動執行 npm install + npx gulp release）
        它會直接改寫 wwwroot 原始檔，且重複執行會疊加 ?v=，產生的差異不要提交
    - 多語系文字來源是根目錄的 SharedResource(RD2017004-製程報工).csv；
        .resx / Resources.js / Enums/*.js 都是 T4 產物，不可手改（走 AddResource.ps1 → BuildResources.ps1）
    - Elmah 與 ElasticAPM 互斥，由 appsettings 的 ElasticApm:Enabled 控制
        （Elmah 只在此鍵存在且為 false 時才註冊；appsettings.json / Produ
    - Redis 連線可選（ConnectionStrings:RedisConnection），未設定時退回 MemoryCache
    - 資料保護金鑰（DataProtection key ring）持久化到 DB（PersistKeysToDb表）；
        JWT 簽章金鑰來自設定 Tokens:IssuerSigningKey，已簽發的 JWT 記錄在 LoginUesrJWT 表
    - Hangfire Server 單 worker、指定佇列 "lcerp"；內建排程 ClearExpiredJWT（每小時，台北時區）
    - RateLimiting 需在端點以 [AuthFilter(..., rateLimiting: true)] 開啟，目前沒有端點啟用
    - NLog 只為 4 個具名 logger 設了寫入規則，JSNLog 送回的前端錯誤沒有對應規則

                  意見回饋管理(Feedback)、關鍵字管理(Keyword)、問卷管理(Questionnaire，選單隱藏)
      【案件管理】案件管理(CustomerIssue)：含案件聊天室、智耕雲 Webhook、版更通知 / 求救
      【統計報表】客戶案件明細表、客戶顧問輔導時數統計表(Report)

        個人資料管理(MyProfile)、Kendo 圖片瀏覽器、通知鈴鐺(Notification)

## 分層慣例（重要）

    1. View       — Razor Views + Kendo UI MVVM 綁定
    2. Controller — 路由、參數驗證，呼叫 Service 後包裝回傳
    3. Service    — 業務邏輯與商業規則，直接注入 CSSDbContext（無 Repository 層）
    4. Logic      — 可選層：只放跨 Service 重用的規則或查詢
    5. DbContext  — EF Core 實體與資料庫

      ⚠ Controller 禁止包含業務邏輯，只做：參數驗證 → 調用 Service → 返回結果
      ▎ 上面 1~5 是由上往下的呼叫順序；Solution 的 Layer1~4 是由下往上編號，兩者不可混用
      ▎ 規範出處：.claude/docs/conventions/core/architecture.md

# RD2023001 (HKLogistics)

> 查核日期：2026-10-29｜分支：master｜commit：62b28de3（2026-10-28）

物流配送管理系統 (Logistics Distribution Management System)，專注冷鏈/農產品配送，
涵蓋派車排線、司機任務、代運/託運管理、箱籃資材庫存、運費結算。

## 分層慣例（規範 vs 實況）

    規範（.claude/docs/共用基礎建設與開發慣例.md）
    - 列表頁 Controller 繼承 BaseManageController，標準寫法由 Controller 私有的 Search() 直接查詢並分頁
    - 資料存取透過注入的 IUnitOfWork<DBEntities> 取得 Repository；資料異
    - 交易邊界只開一層：呼叫端已開交易時 BLL 不可再開；兩種情境都會呼叫的
      選項（範式：DriverWeightSettleBll 的 useTransaction）
    - 沒有明文規定 Controller 與 BLL 的分工

    實況（抽樣 3 條呼叫鏈）
    - 智慧派車：VDAssignCarRouteController.DeleteRoutes（:1459）→ AssignCarRouteCommandBll.DeleteRoutes
      （:1017）→ BLL 自開 CommitInTransaction + Repository.DeleteRange
    - 列表頁：BIUnitController.Index(POST)（:63）→ this.Search()（:94）→ Repository.FindBy（:96），
      不經 BLL；寫入也由 Controller 自開交易
    - 拉板：VDPullPalletController.GetTrips（:202）→ PullPalletBll.GetTrips（:61）→ FindByAsNoTracking

    不一致處
    - 規範寫「透過注入取得 uow」，實況 127 支 Controller 自行 new EFUnitOfWork，只有 8 支 public 建構子接收注入
    - 13 支 BLL 會自行開交易（規範允許），被已開交易的 Controller 呼叫時會發生巢狀交易錯誤

      Route Optimization API optimizeTours。設定鍵 GoogleRouteOptimization.Provider
      （WebAppSettings.config，預設 RoutesComputeRoutes）。

## 核心業務流程（分級秤重）

    1. 起始頁 → QR 登入：從本機 KioskTool 取得 Kiosk 識別，掃碼槍讀員工個人 QR
       → ERP AuthApi/KioskLogin 驗證（需 ERP「分級進貨(Client)」權限）→ 本系統簽發自己的 JWT
    2. 查詢暫收單：輸入 / 掃描單號（GetDocumentByCode）或依日期前後切換（GetDocumentsByDate）
    3. 選擇暫收單 → 進入分級秤重頁（載入既有秤重明細 GetDocumentDetails）
    4. 選擇作物 → 品級 → 規格（三層連動，品級由 ERP 依作物設定回傳；選規格時自動帶入存入倉庫）
    5. 秤重：重量由 KioskTool 即時推送磅秤讀值，數字鍵盤可手動覆寫；選擇棧板（只用於扣重）、箱籃與箱籃數（預設 1）
       → 淨重 = 毛重 −（棧板重 + 箱籃重 × 箱籃數）→ 新增明細（「秤重」或「秤重並列印」）
       （有疑似重複秤重提醒；連上磅秤時存檔後鎖定新增，磅秤回到 0 或手動改了重量才解鎖）
    6. 列印：伺服器以 Spire.Pdf 產生每筆明細的標籤 PDF（含 QR 碼）→ 經 KioskTool 送印；
       秤重明細頁可勾選多筆重印、刪除明細
    7. 分級完成 →「送出分級結果」依序呼叫 CreatePurchaseReturn（新增進貨退出單）→ CommitDocument

## Solution 分層結構（4 Level + 測試）

  src/
  ├── Level1（共用基礎）
  │   └── Core/               — 共用工具、擴充方法
  │
  ├── Level2（資料/領域）
  │   ├── Domain/             — Entities、Enums、ViewModels
  │   ├── DbContexts/         — EF Core DbContext + Migrations
  │   └── LCApiLogics/        — 凌聚共用 API 串接
  │
  ├── Level3（業務邏輯 / 管理服務）
  │   ├── Service.Manage/     — 後台管理業務（CRUD 為主）
  │   ├── TAFT/               — TAFT 生態系統整合
  │   └── EventLogAOPs/       — 事件日誌 AOP 攔截
  │
  ├── Level4（服務層，按業務領域拆分）
  │   ├── Service/            — 核心業務服務
  │   ├── AuthService/        — 認證/授權服務
  │   ├── SeedlingService/    — 種苗培育服務
  │   ├── SensorManageService/— 感測器管理服務（含 EventLogAOP）
  │   ├── VideoService/       — 影音服務（Azure Media Service）
  │   ├── ExcelImportService/ — Excel 匯入服務
  │   ├── ExternalApi/        — 外部 API 串接（病蟲害警報/節水灌溉/出貨/CSS）
  │   ├── NotificationCenter/ — 通知中心（Pool/Send 模式）
  │   ├── WorkNoticeService/  — 農務通知服務
  │   ├── SystemUsageService/ — 系統使用統計服務
  │   └── GrowthForecastingModel/ — 生長預測模型
  │
  └── LCEPM/（主 Web 應用）
      ├── Controllers/         — MVC Controllers（無子目錄，頁面直接由 Views 管理）
      ├── ApiControllers/      — 內部 API（46 個 Controller）
      ├── ERPApiControllers/   — ERP 對接 API（產能/種植計畫）
      ├── FarmtaCloudApiControllers/ — FarmtaCloud 永續農業雲 API（30 個 Controller）
      ├── NTTApiControllers/   — NTT 整合 API
      ├── ProjectApiControllers/ — 專案管理 API（首頁/訂單/使用者）
      ├── Views/               — Razor Views（120+ 個功能模組）
      ├── Jobs/                — Hangfire 排程
      ├── Schedule.cs          — 排程定義（35KB，大量排程任務）
      ├── Swagger/             — Swagger 自訂
      ├── FFMpeg/              — FFMpeg 影音處理
      ├── RptTemplate/         — 報表範本
      ├── Authorization/       — 權限驗證
      ├── ComboManage.cs       — 下拉選單管理（150KB，極大）
      └── _Design/             — SCSS 樣式

  test/
  ├── LCEPM.Service.Tests/    — 服務層測試
  ├── LCEPM.Manage.Tests/     — 管理服務測試
  ├── LCEPM.Core.Tests/       — 核心工具測試
  ├── LCEPM.Domain.Tests/     — 領域測試
  ├── ServiceTests/           — 通用服務測試
  └── PlaywrightTests/        — Playwright E2E 測試

## 外部系統整合

  【ERP】ERPApiControllers — 產能規劃(PlantCapacity) / 種植計畫(PlantPlan)
  【FarmtaCloud】永續農業雲 — 碳足跡盤查/碳標籤申請/ESG績效指標/
                               永續報告/供需媒合/輔導紀錄/永續媒合管理/
                               基線設定/碳平台資料維護（30 個 Controller）
  【NTT】NTT 系統整合
  【外部警報】KSI 稻飛蝨/稻熱病警報、中興大學節水灌溉警報
  【CSS】LjcssApiClient — 客服系統串接（訂單出貨同步）

## 開發重點注意

  - ComboManage.cs 極大（150KB），是所有下拉選單的統一管理中心
  - Schedule.cs 極大（35KB），定義大量 Hangfire 排程任務
  - 多套 ApiController 群組：內部 API / ERP API / FarmtaCloud API / NTT API / Project API
  - Service 層按業務領域拆分為 11 個獨立專案
  - NotificationCenter 採 Pool/Send 模式（與 CSS 專案共通架構）
  - SonarQube 整合（build-sonarqube.dockerfile）
  - Playwright E2E 測試獨立於主方案（PlaywrightTests.sln）
  - CI Pipeline：lcepm-ci-with-e2e-tests.yml
  - 影音處理：Azure Media Service + FFMpeg
  - FarmtaCloud 子系統佔比大，是獨立的永續農業雲平台功能
